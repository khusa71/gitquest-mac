# GitQuest for Mac — build contracts

A desktop app (Electron) that teaches git with **real git** in a **real terminal**, next to live
diagrams of the repo. English only. First slice: setup + Level 1 missions 1.1–1.3, the level map.

## Modules and owners (one agent per folder, never edit another folder)

| Folder | Owner | Runs in | Purpose |
|---|---|---|---|
| `src/shared/` | integrator | both | `repo-types.ts` (RepoState, copied from git-quest), `view-model.ts`, `api.ts`. Read-only for agents; propose changes in your report. |
| `src/realgit/` | realgit agent | main (Node) | Every git call. Contract: `src/realgit/index.ts`. |

## Paths on disk (`defaultPaths()`)

```
~/GitQuest/nova            the story repo the player works in (terminal cwd)
~/.gitquest/gitconfig      curated global config (GIT_CONFIG_GLOBAL) — player's ~/.gitconfig never read or written
~/.gitquest/remotes/nova.git  bare "origin"
~/.gitquest/snapshots/     undo checkpoints
~/.gitquest/progress.json  progress + story position
~/.gitquest/shell/.zshrc   generated by the electron agent
```

Tests must never touch the real home: every function takes `GitQuestPaths`; tests use `defaultPaths(tmpdir)`.

**In-place rule:** the terminal's shell has `~/GitQuest/nova` as cwd. Never delete or rename that directory.
Rebuilds and undo restores empty it (including `.git`) and copy the new content INTO it, so the shell's cwd stays valid.

## Story repo carried forward (game agent)

The repo is one continuous story ("Nova"). `progress.json` stores, together with every repo change,
`position: { missionId, stage: 'entry' | 'after' } | null`. That position is the only truth for what has been applied:

- Start mission N with position `{N, entry}` → resume.
- Position `{N-1, after}` → run N's prelude on the real repo (teammate commits with their author + fixed date), then `{N, entry}`.
- Anything else (out of order, replay of a done mission, null, prelude fails) → rebuild N's canonical entry in a temp dir
  (root + every earlier mission's prelude + reference solution + N's prelude), copy it in place, then `{N, entry}`.
- Mission solved → `{N, after}`; the player's own commits stay in the repo for the next mission.

Setup commands use the web game's syntax (`edit f "x"`, `touch`, `rm`, `git …`) and run through `realgit.runSetupCommands`.
Teammates: Lea Moreau <lea@nova.dev>, Samir Haddad <samir@nova.dev> (check names in git-quest `src/story/actor.ts`).
Setup commits use fixed dates (e.g. 2026-01-05T09:00:00Z + n minutes) so canonical hashes are reproducible.

## Shell hooks protocol (electron agent ↔ game)

The pty runs the player's `$SHELL` (zsh on macOS) with cwd = repo, env = `sandboxEnv(paths, process.env)`, `ZDOTDIR=~/.gitquest/shell`.
The generated `.zshrc` sources the player's own `~/.zshrc` first (with ZDOTDIR pointing at $HOME while it runs), then adds:

```zsh
autoload -Uz add-zsh-hook
_gq_preexec() { printf '\e]777;gq;cmd;%s\a' "$(printf '%s' "$1" | base64 | tr -d '\n')"; }
_gq_precmd()  { local c=$?; printf '\e]777;gq;done;%s\a' "$c"; }
add-zsh-hook preexec _gq_preexec
add-zsh-hook precmd _gq_precmd
```

Main strips every `ESC ] 777 ; gq ; … BEL` sequence from pty output before sending it to the renderer, remembers the
decoded command on `cmd`, and on `done` calls `game.afterCommand(command, exitCode)` and pushes the returned view.
An fs watcher on the repo (debounced 300 ms) calls `game.afterCommand(null, null)` for changes made outside the terminal.

## Scoring (game agent)

Stars like the web game: commands used ≤ par → 3, ≤ par + 2 → 2, else 1. Commands that don't count: failed ones (exit ≠ 0),
read-only ones (`git status|log|diff|show|help|branch` without args, `ls`, `cat`, `cd`, `pwd`, `clear`), and anything not starting with `git`.

## Design (ui agent)

GitHub Primer dark palette, system font stack, SF Mono / ui-monospace for code. Colour only carries meaning
(branch lanes, disk = attention #d29922, index = success #3fb950, check pass/fail). Diagram-first: history as snapshot cards,
the three areas as Disk → Index → HEAD with forward and backward commands.

## Voice (second build round)

| Folder / file | Owner | Purpose |
|---|---|---|
| `native/speech/`, `src/main/speech.ts`, `scripts/build-speech.mjs`, `scripts/patch-dev-plist.mjs` | speech agent | On-device speech recognition: a small Swift CLI (`SFSpeechRecognizer`, on-device when supported, git vocabulary as contextual strings) that prints one JSON line per transcript `{"text","final"}` to stdout; `speech.ts` spawns/kills it and reports `VoiceStatus.speech`. Compiled with `swiftc` to `resources/bin/gitquest-transcribe`. |
| `src/main/tutor.ts`, `src/shared/spoken.ts` | tutor agent | Claude tutor (`@anthropic-ai/sdk`, already installed) + encrypted key storage (safeStorage → `~/.gitquest/tutor-key.bin`). `spoken.ts` is pure: turns spoken words into a shell command ("git add app dot ts" → `git add app.ts`). |
| `src/renderer/` voice UI | ui agent | Mic button + push-to-talk, transcript, tutor conversation, read-aloud (Web Speech `speechSynthesis`, macOS voices, offline), API key settings. |
| `src/main/index.ts`, `src/preload/index.ts` | integrator | IPC wiring for `GitQuestApi.voice` (see `src/shared/api.ts`). |

Routing a final transcript (renderer): if `toCommand(text)` from `src/shared/spoken.ts` returns a command → write it to the terminal WITHOUT Enter and say "Press Enter to run"; otherwise → `voice.ask(text)` and speak the reply. The tutor never runs commands itself.
